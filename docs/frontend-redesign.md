# PulseFeed 前端重构方案（S23 提案）

> 状态：草案，待评审。本文只定义设计与实施路径，不含生产代码。
> 原型：`docs/prototype/direction-a.html`（推荐方向，含 Feed + 登录）、`direction-b.html`、`direction-c.html`（对比草图）。
> 现状基线：`apps/web/src/App.jsx`（815 行单文件）+ `styles.css`（374 行），无路由、无组件拆分、无断点、无焦点样式。

---

## 1. 背景与目标

现状问题已在界面评估中量化：单列 640px、卡片封面退化为 `#id`、字号只有 26/18/15/13/12 五档、零 `@media`、按钮高约 28px、无 `:focus-visible`。结论是"功能齐全但产品感像后端自测面板"。

本轮重构目标：

1. **观感达到 2026 年内容产品的及格线**：有媒体、有层级、有动效、有状态反馈。
2. **结构可维护**：单文件拆成页面 + 组件，路由可深链。
3. **不牺牲已有能力**：四场景、互动、发布、消息、播放配置全部保留，API 契约不变（除可选的媒体字段扩展）。
4. **少加依赖**：新增运行时依赖不超过 1 个。

---

## 2. 设计方向（3 选 1）

### 方向 A：暗色沉浸内容流（推荐）

- **参考气质**：视频流产品的夜间形态 + 工具类产品的克制排版。视觉上接近"夜间流媒体编辑部"，而不是"后台管理面板"。
- **适配场景**：桌面浏览为主、移动端为辅；内容以短视频 + 封面为主，适合长时间浏览与深色环境。
- **形态**：桌面 3 列栅格（641–1279 为 2 列，≤640 单列）；卡片 16:9 封面 + 悬停播放；纯黑底 + 红 `#FE2C55` 主强调，青 `#25F4EE` 仅用于焦点环、播放计数与品牌渐变收尾。
- **优点**：与现有深色底成本最低；暗色让封面与数字更突出；栅格化直接解决桌面死白；移动端降为单列即可复用同一套卡片。
- **缺点**：暗色对图片质量要求高，封面缺失时更明显（需靠渐变占位兜底）；长时间阅读正文不如亮色舒适。

### 方向 B：明亮杂志栅格

- **参考气质**：图片社区 / 独立杂志的网页版：暖白纸感、衬线标题、细分隔线、编辑化排版。
- **适配场景**：品牌向、内容策展向、以图文和封面为主的浏览；适合白天与办公环境。
- **形态**：暖白 `#F7F6F2` 画布，衬线展示字体，2 列错落栅格（masonry），朱红强调色 `#E5402A`，卡片以图为主、标题在上。
- **优点**：差异化最强，一眼区别于常见视频 App；排版气质好，适合对外展示与截图传播。
- **缺点**：与"短视频播放"的产品事实有张力；深色视频播放器放进去会有割裂感；改动量最大（配色、字体、栅格全部重来）。

### 方向 C：视频优先全屏流

- **参考气质**：移动端短视频的全屏单条体验（上滑切换、右侧操作栏、底部信息层）。
- **适配场景**：移动端优先、单条消费、强沉浸。
- **形态**：纯黑画布，单条 9:16 满屏；桌面居中一个 420×820 的"舞台"，两侧留黑。
- **优点**：产品语义最准（本来就是 clip 流）；移动端体验上限最高；动效空间大。
- **缺点**：桌面端浪费横向空间；信息密度低，四场景切换与消息/配置等非流式页面难以统一；需要真实视频与首帧，否则原型就是空壳。

### 对比与推荐

| 维度 | A 暗色沉浸内容流 | B 明亮杂志栅格 | C 视频优先全屏流 |
|---|---|---|---|
| 差异化 | 中 | 高 | 高 |
| 与产品事实贴合 | 高 | 中 | 高 |
| 桌面体验 | 高（3 列栅格） | 高（错落栅格） | 低（居中舞台） |
| 移动体验 | 高（单列） | 中 | 极高 |
| 改动量（相对现状） | 中 | 大 | 大 |
| 对封面/视频依赖 | 中 | 高 | 极高 |
| 非流式页面（发布/消息/配置）可统一 | 高 | 高 | 低 |
| 风险 | 低 | 中 | 高 |

**推荐 A。** 理由：它是唯一能在"桌面栅格 + 移动单列 + 发布/消息/配置"之间共用一套 shell 的方向，改动集中在前端且不依赖新的后端字段；同时用红/青强调 + 16:9 媒体卡片 + 骨架屏，足以把"后台 demo"的观感抬到产品级。C 可作为 A 的移动端演进方向（A 的卡片点击后进入全屏 sheet，即为 C 的形态），B 留作品牌化备选。

## 3. 设计 token 体系（A 方向）

### 3.1 中性色阶（含层次背景）

| Token | 值 | 用途 |
|---|---|---|
| `--pf-bg` | `#000000` | 画布与页面背景（纯黑） |
| `--surface-1` | `#161823` | 卡片 / 面板 |
| `--surface-2` | `#1C1C1E` | 浮层、输入框、悬停态 |
| `--surface-3` | `#26272B` | 骨架屏、次级块 |
| `--line` | `rgba(255,255,255,0.08)` | 常规分割线 |
| `--line-strong` | `rgba(255,255,255,0.16)` | 强边框、导航选中 |
| `--text-1` | `#FFFFFF` | 主文本 |
| `--text-2` | `rgba(255,255,255,0.75)` | 次要文本（作者、说明） |
| `--text-3` | `rgba(255,255,255,0.45)` | 三级文本 / 占位符 |

### 3.2 强调色与语义色

| Token | 值 | 用途 |
|---|---|---|
| `--brand` | `#FE2C55` | 只给主操作与点赞（主按钮、点赞激活） |
| `--brand-hover` | `#FF4D70` | 悬停 |
| `--brand-press` | `#E01F46` | 按下 |
| `--brand-soft` | `rgba(254,44,85,0.14)` | 仅保留 token，常规界面不用红底块 |
| `--cyan` | `#25F4EE` | 只给焦点环、收藏激活与极少量标签（如未读数） |
| `--cyan-soft` | `rgba(37,244,238,0.12)` | 上述小面积底色 |
| `--success` | `#34D399` | 成功提示 |
| `--warning` | `#FFB020` | 警示、待处理 |
| `--error` | `#FF6B6B` | 错误、失败 |
| `--info` | `#60A5FA` | 中性信息 |

配色纪律：红与青不同时出现在同一区域抢视线；场景选中、分段控件选中、空态图标等一律用中性明暗块（`--surface-2/3`）而非强调色。

对比度：`--text-1` / `--pf-bg` ≈ 21:1；`--text-2` / `--surface-1` ≈ 10:1；`--text-3` / `--surface-1` ≈ 4.6:1（仅用于非关键信息，不承载必读内容）。白字 / `--brand` ≈ 3.7:1，只用于大字号与按钮文字，正文不叠在红底上；`--cyan` / `--pf-bg` ≈ 14:1，用于焦点环足够醒目。

### 3.3 字号阶梯与行高

| Token | 字号 / 行高 | 字重 | 用途 |
|---|---|---|---|
| `--fs-display` | 32 / 36（-0.02em） | 700 | 登录页品牌标题、空态大标题 |
| `--fs-h1` | 24 / 30（-0.01em） | 700 | 页面标题 |
| `--fs-h2` | 20 / 26 | 600 | 区块标题 |
| `--fs-title` | 16 / 22 | 700 | 卡片标题（最多 2 行，加重以拉开与 meta 的层级） |
| `--fs-body` | 14 / 22 | 400 | 正文、表单 |
| `--fs-caption` | 12 / 18 | 400 | 作者、时间、辅助说明 |
| `--fs-micro` | 11 / 16（`tabular-nums`） | 500 | 计数、时长、角标 |

数字统一 `font-variant-numeric: tabular-nums`，避免计数跳动。

### 3.4 间距、圆角、阴影

- **间距基数 4**：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64 / 80`。
- **圆角**：`--r-xs 4`（角标）、`--r-sm 8`（按钮/输入/导航）、`--r-md 10`（卡片/封面/骨架）、`--r-lg 12`（面板/登录卡）、`--r-pill` 仅用于头像与必须的胶囊角标。卡片不再使用 16px 以上的圆角，避免"玩具感"。
- **分割线**：统一 hairline `1px solid var(--line)`（`rgba(255,255,255,.08)`），不使用阴影代替分割线。
- **阴影**：只保留两级——`sm 0 1px 2px rgba(0,0,0,.35)`（悬停微反馈）、`md 0 12px 32px rgba(0,0,0,.45)`（仅弹层/浮层）。常态层级靠 `--surface-1/2/3` 明暗块表达，不叠加发光。
- **层级**：`--z-sticky 10`、`--z-dropdown 20`、`--z-modal 30`、`--z-toast 40`。

### 3.5 动效

| Token | 值 | 用途 |
|---|---|---|
| `--dur-fast` | 120ms | 颜色、边框、按下、hover |
| `--dur-base` | 200ms | 弹层/Sheet 进出、骨架淡出 |
| `--ease-standard` | `cubic-bezier(.2,.8,.2,1)` | 通用 |

原则：只动状态变化（hover、press、加载淡出），**不做入场动画**，不叠加位移 + 缩放 + 发光。骨架屏的微光是加载状态的一部分，保留；`@media (prefers-reduced-motion: reduce)` 下全部动效降为 `0.01ms`。

### 3.6 尺寸与栅格

- 容器：`--w-app 1240px`（带 24px 边距）、`--w-content 1120px`、`--w-narrow 420px`（登录/配置）。
- 断点：`≤640` 移动（1 列）、`641–1279` 平板（2 列）、`≥1280` 桌面（3 列）。
- 12 列栅格，槽宽 24（桌面）/ 16（移动）。

## 4. 信息架构与页面布局

顶层导航改为路由（详见 §7）：

```
/login                登录 / 注册
/                     Feed（?scene=latest|hot|following|for-you）
/clip/:clipId         卡片详情 / 播放（桌面弹层，移动全屏 sheet）
/publish              发布
/messages             消息
/settings/playback    播放配置
```

### 4.1 登录 / 注册

- **桌面**：两栏，左 1.1fr 品牌舞台（mesh 渐变 + 字标 + 一句话定位 + 3 条能力点），右 1fr 表单卡（宽 420）。
- **移动**：单列，品牌区压缩为顶部 120px 区块。
- **结构**：登录/注册用分段控件切换；字段"账号 / 密码 /（注册）昵称"；主按钮全宽 48px。
- **状态**：默认；提交中（按钮内联 spinner + 文案变"登录中…"）；失败（字段下方红字 + 表单顶部 banner，`aria-live`）；成功（跳转 Feed，首屏骨架）。
- **空/错态**：账号不存在、密码错误分别给可读文案，不显示后端原始错误码。

### 4.2 Feed（四场景）

- **顶栏 64px sticky**：字标、主导航、头像与退出；场景切换位于内容区顶部。
- **场景行**：最新 / 热门 / 关注 / 推荐，选中态用 `--surface-3` 底 + 白色字（中性明暗块，不用红/青强调），未选中为 `--text-2`。
- **栅格**：≥1280 三列、641–1279 两列、≤640 单列；卡片间距 20。
- **卡片分区**：
  1. 封面 16:9：时长角标右下、悬停播放键居中（半透明黑底 + hairline 描边，无发光）、右上场景角标；
  2. 标题 16/22、字重 700，最多 2 行；
  3. 作者行：20px 圆形头像（中性色块首字） + 昵称 12px `--text-3` + 发布时间 12px `--text-3`（meta 主动弱化）；
  4. 操作栏：点赞 / 收藏 / 评论 / 分享，图标 + `tabular-nums` 计数，命中区 44px。
- **加载态**：首屏 6 个骨架卡（封面块 + 两行条 + 操作条），骨架微光扫过（唯一保留的循环动效）。
- **空态**：居中图标 + "这个场景还没有内容" + 主按钮"去发布"。
- **错误态**：顶部内联横幅（`--error` 左边框）+ "重试"按钮，保留已有内容不清空。
- **到底**：细分隔线 + "已经到底了" 12px 三级字。
- **翻页**：底部追加 3 个骨架卡；滚动触发，不用按钮。

### 4.3 卡片详情 / 播放

- **桌面**：弹层 1080×720，左 16:9 播放器（60%），右信息与评论（40%，评论可滚动，底部输入框吸底）。
- **移动**：全屏 sheet，9:16 视频在上，信息与操作在下，评论抽屉上滑。
- **状态**：缓冲中转圈；加载失败"播放失败，点击重试"；自动播放被拦截时显示大播放键；点赞/收藏乐观更新。
- **返回**：桌面 Esc / 点遮罩；移动下滑或返回键关闭。

### 4.4 发布

- **桌面**：两栏 1.2fr / 1fr。左：拖拽上传区（虚线框，高 360，drag-over 时边框变 `--brand` 并显示"松手即可上传"），选中后显示首帧预览 + 文件名 + 大小 + 移除。右：标题输入（计数 0/80）、封面上传（16:9 预览，可"从首帧截取"）、发布按钮。
- **移动**：单列，上传区在上。
- **状态**：空闲 → 拖入 → 上传中（进度条 + 百分比，可取消）→ 创建中（按钮 spinner）→ 成功（toast"已发布"并跳 Feed 最新，新卡片短暂高亮）→ 失败（保留所选文件 + 重试按钮）。
- **校验**：标题必填、文件类型白名单、文件大小上限；错误就地展示。

### 4.5 消息

- **头部**：标题 + 未读计数 + "全部已读"（无未读时禁用）。
- **筛选**：全部 / 未读 / 互动 / 系统（胶囊）。
- **行**：56–64px，左 40px 头像 + 类型角标（心/评论/关注），中间"昵称 + 动作 + 目标"一句话，右侧相对时间；未读左侧 3px `--brand` 竖条 + 圆点。
- **状态**：骨架 5 行；空态"还没有消息"；错误横幅 + 重试；点击行即已读并更新角标。

### 4.6 播放配置

- **容器** 720px，单卡分组：
  1. 预加载条数：分段控件 0 / 3 / 5 / 10 + 自定义数字输入；
  2. QoS 采样率：滑杆 0–100%，右侧数值气泡实时更新；
  3. 预加载列表："查看"按钮展开为 clip 卡片 chips（点击可跳详情）。
- **状态**：加载骨架；保存中 spinner；成功 toast"配置已保存"；失败保留输入并提示；有未保存修改时底部吸底栏出现"保存 / 重置"。

## 6. 媒体呈现方案

| 项 | 方案 |
|---|---|
| 封面比例 | 16:9，`aspect-ratio: 16 / 9`，`object-fit: cover`，圆角 12（卡片上部） |
| 首帧 | `<video preload="metadata" muted playsinline src="{video_url}#t=0.1">`，仅卡片进入视口 200px 内才挂载，离开即卸载 |
| 无图占位 | 由 `clip_id` 哈希取色相，生成 mesh 渐变（3 个色停） + 标题首字（32px/700，40% 白），悬停时渐变缓慢位移；不显示时长角标 |
| 时长 | 有后端字段用 `duration_ms`；无则用 `loadedmetadata` 读 `duration`，加载前不显示 |
| 播放形态 | 桌面：悬停静音内联播放，点击进入详情弹层带声；移动：点击直接进全屏 sheet。理由：避免栅格中多条视频同时出声 |
| 图片加载 | `loading="lazy"` + `decoding="async"`；失败时 `onError` 切回渐变占位 |

### 需要后端配合（风险项）

1. **`duration_ms`**：上传时用 ffprobe 读取并落库。影响：`pf_clips` 加列 + `migration` 模型、`domain/clip` 实体、clip DTO、feed 查询 `SELECT` 列表、测试夹具。约 0.5 人日。
2. **封面自动生成**：无 `cover_url` 时由后端抽首帧存 `/uploads/cover/`。影响：上传 handler（依赖 ffmpeg，镜像已装）、clip 创建流程。约 0.5 人日。
3. **宽高比字段**（可选）：非 16:9 素材裁切策略。影响：同上。

不做后端扩展时：前端仍可用渐变占位 + 客户端读时长，视觉不受阻，只是时长角标出现稍晚、封面无法自动生成。建议 P2 前完成 1、2 两项。

## 7. 技术选择

| 议题 | 推荐 | 理由 |
|---|---|---|
| 路由 | **引入 `react-router-dom` v6** | 现在 tab 状态无深链、无返回键；详情/发布/消息需要独立 URL。仅 1 个运行时依赖，体积约 20KB gzip。若拒绝依赖，可自写 40 行 hash 路由，但后续查询参数与嵌套路由成本更高 |
| 图标 | **内联 SVG sprite（零依赖）** | 需要图标不超过 15 个；图标库（lucide-react 等）会引入一个依赖 + tree-shaking 不确定性。集中在 `Icon.jsx`，按 16/20/24 输出 |
| 样式 | **CSS 变量 + CSS Modules** | Vite 原生支持，零配置；token 集中在 `styles/tokens.css`，组件样式就近。不引入 Tailwind：本项目组件数量少，工具类收益不抵配置与阅读成本 |
| 字体 | **系统字体栈** | `-apple-system, "PingFang SC", "Segoe UI", "Noto Sans SC"`；不加载 Web Font，首屏零字体请求。标题靠字重与字距做层级，数字用 `tabular-nums`。若品牌需要衬线/展示体，再自托管 1 个可变字体（仅 B 方向需要） |
| 状态管理 | **沿用 `useState` + 自写 `useApi` hook** | 页面级状态足够；不引入 Redux/SWR/TanStack Query。`useApi` 统一 loading/error/重试/取消 |
| 组件库 | **不引入** | 视觉目标是定制化，组件库改造成本高于自建 15 个小组件 |

新增依赖清单：`react-router-dom`（唯一）。其余全部复用现有 React 18 + Vite 5。

## 8. 响应式与无障碍清单

### 响应式

- [ ] 断点：`≤640` / `641–1279` / `≥1280`。
- [ ] 栅格列数：1 / 2 / 3；间距 16 / 20 / 24。
- [ ] 移动端卡片改为纵向全宽，操作栏不换行，按钮命中区 ≥44×44。
- [ ] 移动端详情用全屏 sheet，桌面用弹层；断点处不做同一布局硬缩放。
- [ ] 顶栏在移动端收起搜索，场景行可横向滚动且隐藏滚动条。
- [ ] 字号不随视口缩小，只改布局；正文最小 14px。
- [ ] 横屏/竖屏、320px 极窄屏不出现横向滚动。

### 无障碍

- [ ] 全局 `:focus-visible { outline: 2px solid var(--cyan); outline-offset: 2px; }`，禁止 `outline: none` 无替代。
- [ ] 对比度：正文 ≥4.5:1，大字号 ≥3:1；`--text-3` 不用于必读信息。
- [ ] 语义：`header/nav/main/section/article/footer`；卡片用 `<article>`，标题用 `<h3>`。
- [ ] 场景切换用 `role="tablist"` + `aria-selected`，支持左右方向键。
- [ ] 图标按钮带 `aria-label`，计数变化用 `aria-live="polite"`。
- [ ] 图片 `alt` 用标题；纯装饰渐变 `aria-hidden="true"`。
- [ ] 弹层：焦点陷阱、Esc 关闭、关闭后焦点回到触发元素。
- [ ] 表单：`label` 显式关联，错误用 `aria-describedby` + `aria-invalid`。
- [ ] Toast：`role="status"`，成功/失败文案可读，不依赖颜色。
- [ ] 支持 `prefers-reduced-motion`；支持键盘完成点赞/收藏/切场景。
- [ ] 页面标题随路由变化（`document.title`）。

## 10. 风险与不做的事

- **不做**：不引入组件库、不引入 CSS 框架、不做 SSR、不改 API 契约（除可选字段）、不重写后端。
- **风险 1**：视频素材缺失时，卡片仍以渐变占位呈现；需接受"无图也好看"的兜底设计。
- **风险 2**：路由引入后旧 tab 状态逻辑需删除，可能出现短暂的导航状态丢失；P0 用兼容壳承接。
- **风险 3**：`preload="metadata"` 在弱网下会拖慢首屏；用视口懒挂载 + 先封面后视频缓解。
- **风险 4**：若后续要做方向 C 的移动端全屏流，需在 P2 后单独立项，不复用 P1 的弹层逻辑。
- **原型局限**：原型为纯静态 HTML/CSS/JS，封面使用渐变占位（当前环境图片生成接口返回固定图，无法产出多张不同封面），交互仅演示状态切换，不连接任何接口。
